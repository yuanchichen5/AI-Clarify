## 问题一：磁盘空间耗尽导致开发工具链全故障

### 1. 问题描述
执行 `npx create-next-app` 脚手架初始化时，`execute_code` 工具开始报
`Errno 28: No space left on device`，随后 terminal 输出捕获、read_file 读取、
文件重定向等工具链路全部退化（输出为空 / 文件 0 字节），开发一度中断。

### 2. 原因分析
- npm / npx 的缓存默认位于 `C:\Users\SKY\AppData\Local\npm-cache`，
  `npx create-next-app --help` 触发完整包下载，将原本剩余空间极小的 C 盘耗尽；
- 磁盘写满后，沙箱无法在 `%TEMP%` 创建脚本临时文件，所有依赖临时文件的工具随之失效；
- 该现象与 Windows 主机已知行为一致（磁盘满 → 全工具链降级）。

### 3. 改进方案
- 将 npm 缓存目录迁移至剩余空间充足的 G 盘：`npm config set cache G:\npm-cache`；
- 清理 `%TEMP%`、npm-cache、各类构建缓存，恢复 C 盘空间；
- 后续安装操作一律显式指定缓存位置，避免再次写满系统盘。

### 4. 实施
- 后台子代理执行清理：删除 npm-cache、清空 Temp、清理 pip/uv/yarn/pnpm 缓存；
- 将 npm cache 全局配置指向 `G:\npm-cache`；
- 重新验证工具链（execute_code / 磁盘查询恢复可用）。

### 5. 验证
- 磁盘查询恢复：C 盘可用空间 2.0GB（清理前 <100MB），G 盘 273GB；
- execute_code 恢复正常，脚手架创建与依赖安装顺利执行；
- 结论：问题解决，缓存已永久迁移 G 盘。

## 问题二：Windows 中文路径下 webpack 构建报 EISDIR

### 1. 问题描述
项目位于 `G:\第二周\Clarify-AI智能笔记整理师`（含中文路径），
执行 `npm run build` 报错：
`Error: EISDIR: illegal operation on a directory, readlink 'G:\第二周\...\src\app\page.tsx'`，
随后错误随机指向其他文件（favicon.ico、next 包内 _app.js 等），构建持续失败。

### 2. 原因分析
- Node.js 在 Windows 上对含非 ASCII（中文）字符的路径执行 `fs.readlink` 时返回 EISDIR
  （libuv 层已知兼容性问题）；
- webpack 在解析依赖时会对模块路径做符号链接探测（readlink），首次触发即抛错；
- 与文件本身是否为符号链接无关，属于路径编码层面的问题。

### 3. 改进方案
- 在 `next.config.ts` 的 webpack 配置中：
  - `config.resolve.symlinks = false`：关闭符号链接解析（本项目不使用 node_modules 符号链接）；
  - `config.cache = false`：关闭 webpack 文件系统缓存快照（快照阶段同样触发 readlink）。

### 4. 实施
- 更新 `next.config.ts`，加入上述两项配置；
- 删除脚手架默认的 `src/app/favicon.ico`（默认图标非必需，且第一个触发该错误）。

### 5. 验证
- `npm run build` 构建通过，产物正常输出到 `.next/`；
- 结论：问题解决，方案已作为项目标准配置保留并注释说明原因。

## 问题三：并发 npm 安装导致依赖目录被清空

### 1. 问题描述
依赖安装完成后，`node_modules/@supabase` 目录为空、prettier 等包缺失，
而 `package-lock.json` 中 792 个包全部登记在册，`npm run build` 报
`Module not found: Can't resolve '@supabase/ssr'`。

### 2. 原因分析
- 安装过程中多次并发/顺序执行 `npm install`，且期间手工重写 package.json 覆盖了
  npm 已写入的新增依赖，导致后续 `npm install` 按旧清单对账时把包当作「多余」删除；
- 根因是「安装进行中改动 package.json + 重复并发安装」的竞态。

### 3. 改进方案
- 规范化流程：先一次性写全 package.json（含全部依赖与正确分区），再执行单次安装；
- 安装期间禁止任何对 package.json / 依赖目录的写操作；
- 清理 node_modules 与 package-lock.json 后全量重装，杜绝增量对账的歧义。

### 4. 实施
- 修正 package.json 依赖分区（supabase 入 dependencies，prettier 系入 devDependencies）；
- 删除 node_modules 与 package-lock.json；
- 后台执行单次 `npm install --no-audit --no-fund`。

### 5. 验证
- node_modules 完整重建，@supabase/supabase-js、@supabase/ssr、prettier 等全部就位；
- `npm run build` 通过（无 Module not found）；
- 结论：问题解决，后续安装一律单次完成、期间零写入。
