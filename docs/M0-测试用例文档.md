## 六、数据库与安全（M0-3 静态验收）

> 验收方式：对 `supabase/migrations/0001_init.sql` 做静态审查；具备 Supabase 环境时在 SQL Editor 执行并核对。

| 编号 | 优先级 | 用例名称 | 检查点 | 预期结果 |
|------|--------|----------|--------|----------|
| M0-TC-130 | P0 | 表完整性 | 对照 §4.2 数据模型逐表核对 | folders / notes / knowledge_points / difficulties / note_embeddings / review_plans / quizzes / quiz_attempts / conversations / messages / jobs / profiles 全部建表 |
| M0-TC-131 | P0 | 向量扩展 | 检查 embedding 字段 | `vector(1536)` 类型 + HNSW 索引（`vector_cosine_ops`） |
| M0-TC-132 | P0 | RLS 全覆盖 | 逐表检查 | 所有用户数据表 `enable row level security`，无遗漏表 |
| M0-TC-133 | P0 | 策略正确性 | 检查 policy 定义 | 全部基于 `auth.uid()` 与 `user_id` 比对；子表（knowledge_points 等）通过父表 user_id 传递校验 |
| M0-TC-134 | P0 | 跨用户隔离（GIVEN-WHEN-THEN） | GIVEN 用户 A 登录 WHEN 以 A 的 Token 查询 B 的笔记 THEN | 查询返回 0 行（RLS 拦截），不暴露任何数据 |
| M0-TC-135 | P0 | 索引完整性 | 核对 §5.3 索引清单 | notes(user_id,updated_at)、folders(user_id,parent_id)、knowledge_points(note_id) 等复合索引存在 |
| M0-TC-136 | P1 | updated_at 触发器 | 检查迁移脚本 | 各业务表挂接 `set_updated_at()` 触发器 |
| M0-TC-137 | P1 | 脚本可重复执行 | 同一脚本执行两次 | `create if not exists` 语法保证幂等，不报错 |
